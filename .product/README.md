## 功能包文件约定

PRD 清洗流程产出同前缀的四份文件；每份头部标注 `<功能包名> · PRD 版本 <x.y>`，四份版本一致。未知值留空待填，不臆造。

| 文件 | 必需内容 |
| --- | --- |
| `<功能包>-prd.md` | 使用对象、范围、目标、预期功能 `P*-**`、异常边界、本期不包含、验收标准 `AC-*`、待决事项 |
| `<功能包>-schedule-quote.md` | 工期、报价、付款节点、里程碑；与 PRD 功能 ID 的覆盖关系 |
| `<功能包>-delivery-status.md` | PRD/UI 批准各自的日期与确认人；研发、测试、部署、客户验收四类状态；阻断内容、影响范围、恢复条件、证据 |
| `<功能包>-traceability.md` | UI ID、资产位置、批准状态，无 UI 标记 `UI-N/A`；功能 ID → UI、路由、前端、后端、API、数据、迁移、测试、相关 `.agents` |

需求或反馈的详细条目在实际启动产品任务时落盘，再进入 Loop。本次未创建产品规范或四份空功能包文件。提示词库中的《PRD清洗提示词》《Loop工程提示词》未随仓库提供，执行时需取得对应内容。
